Business use case · Concept for discussion

Better stories start before the ticket.

Help people turn a rough idea into a useful work item, without turning ticket creation into an interrogation.

The opportunity

Missing context is often discovered only after a ticket is reviewed. An assistant can help the author clarify the outcome and expected behavior while the idea is fresh, then leave the final judgment with the person writing it.

A lightweight writing journey

01

Start with an idea

The author shares a rough description in a conversation.

02

Clarify what matters

The assistant structures a Story and asks only targeted questions about the outcome, audience, and observable acceptance criteria.

03

Review a draft

Unknown facts stay visible. The author reviews the draft; nothing is created without explicit approval.

04

Improve after creation

An advisory check can flag remaining gaps on the created ticket without blocking work.

One assistant, two useful moments

The same assistant could help write a Story before creation and review it afterward. A first trial can use a manually opened conversation; more convenient entry points can follow if people find it valuable.

What should a pilot tell us?

  • Do people choose the help when it is offered?
  • Which questions improve clarity, and which feel burdensome?
  • Is writing assistance more valuable than feedback after creation alone?
  • What is the simplest entry point people will actually use?
This is a product concept, not a deployed integration or a mandatory quality policy.
